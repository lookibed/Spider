Перенос `Spider` с `ffi` на чистые таблицы Lua — это **полная переработка бэкенда компилятора**. Вы фактически выбрасываете текущую реализацию «линейной памяти» и пишете новую на языке Lua (и в генераторе кода на Rust).

Это «операция на открытом сердце». Вот пошаговый план, как к этому подступиться.

*   **ЦЕЛЬ:** Переписать таргет lua-jit чтобы он конвертировался в Lua БЕЗ FFI (как это уже делает Luau таргет)

### Предупреждение
*   **Производительность:** Она упадет в 50–100 раз. Доступ к `ffi` указателю — это одна инструкция процессора. Доступ к таблице Lua — это хэш-поиск, проверка метатаблиц и аллокация объекта.
*   **Сложность:** Вам нужно владеть Rust на уровне выше среднего, так как `Spider` — это компилятор, написанный на Rust.

---

### Этап 1: Анализ генератора кода (Rust)
Вам нужно найти места, где Spider «хардкодит» использование `ffi`.

1.  **Исследование репозитория:** Откройте исходный код `Spider` (Rust). Ищите директорию `codegen`. Скорее всего, логика генерации Lua-кода находится в файлах, отвечающих за `targets/luajit.rs` или `targets/luau.rs`.
2.  **Поиск шаблонов:** Найдите в Rust-коде строки, содержащие `ffi.cdef`, `ffi.cast`, `ffi.C.malloc`. Это и есть «сердце» проблемы. Эти строки — шаблоны, которые компилятор просто вставляет в выходной файл.

### Этап 2: Проектирование «Чисто-Lua» рантайма
Вместо `ffi` вам нужно создать класс/таблицу, эмулирующую память.

1.  **Замена `ffi.C.malloc`:**
    *   **Было:** `ffi.C.malloc(size)`
    *   **Станет:** `local memory = {}` (или `local memory = table.create(size, 0)` в Luau для скорости).
2.  **Реализация Memory Load/Store:**
    *   Вам придется заменить генерацию чтения: `ffi.cast("uint8_t *", ptr)[offset]` на простую индексацию таблицы: `memory[offset]`.
    *   Для 32-битных и 64-битных данных придется написать «декодеры» (функции, которые собирают 4 или 8 байт из таблицы в одно число Lua), так как в таблице у вас будут лежать только байты.

### Этап 3: Модификация Rust-генератора (Самый сложный этап)
Теперь нужно заставить `Spider` генерировать другой код.

1.  **Удаление `ffi.cdef`:** Найдите функцию в Rust, которая пишет `ffi.cdef` в выходной файл, и удалите её.
2.  **Замена структуры памяти:**
    *   Вместо генерации `struct Memory { ... }` (как сейчас в `test.lua`), перепишите генератор так, чтобы он вставлял в начале Lua-файла функцию-конструктор памяти.
    *   **Пример того, что должен генерировать Rust:**
        ```lua
        -- Вместо ffi.cdef и ffi.C.malloc
        local function create_memory(size)
            local mem = {}
            for i = 1, size do mem[i] = 0 end
            return mem
        end
        ```
3.  **Переписывание инструкций Load/Store:**
    *   Найдите в Rust-коде функцию, которая генерирует `I32Load` или `I32Store`.
    *   Сейчас она генерирует вызов `ffi`.
    *   Вам нужно переписать её так, чтобы она генерировала вызов вашей функции чтения из таблицы, например: `read_i32(memory, address)`.

### Этап 4: Реализация операций с типами
WASM оперирует `i32` (целые числа с переполнением). В Lua числа — это `double` (float). 
*   Ваша чистая Lua-реализация `read_i32` должна уметь делать **bitwise operations** (побитовые операции), чтобы имитировать переполнение 32-битного числа.
*   Используйте библиотеку `bit` (если это LuaJIT) или `bit32` (для Lua 5.2+). Это единственный способ сделать «честные» вычисления без `ffi`.

### Этап 5: Рефакторинг `rt_memory_grow`
В `test.lua`, который мы видели ранее, была функция `rt_memory_grow` через `realloc`. 
*   В чистом Lua для таблиц `realloc` не существует. Вам придется либо использовать `table.insert` / `table.remove` (очень медленно), либо заранее аллоцировать таблицу максимального размера (что сожрет много RAM). 
*   Вам нужно переписать эту функцию в Rust-генераторе так, чтобы она просто расширяла таблицу или выбрасывала ошибку при достижении лимита.

### Итоговый чек-лист действий:
1.  **Найти** в Rust-проекте все строки `ffi.`.
2.  **Написать** на Lua вспомогательный файл (runtime), который реализует `read_i32`, `write_i32` через таблицы.
3.  **Заменить** в Rust-генераторе вызовы `ffi` на вызовы этих новых функций.
4.  **Убрать** все `ffi.cdef` из шаблонов вывода.
5.  **Пересобрать** `spider-cli` (`cargo build --release`).
6.  **Запустить** `spider-cli` и проверить, что `test.lua` больше не содержит слов `ffi` и `cdef`.

**С чего начать прямо сейчас?**
Откройте файл `codegen/src/target/luajit.rs` (или как он там называется) в репозитории `Spider`. Найдите функцию, которая отвечает за генерацию пролога (начальных строк кода). Именно там сейчас «зашиты» те самые `ffi.cdef`. Попробуйте просто закомментировать их в Rust и пересобрать `spider-cli`. Вы сразу увидите, на каких этапах компиляции компилятор падает и требует `ffi`. Это будет вашей «картой» правок.

**Запуск обязательного теста**
Выполните `spider-cli test.wasm -t lua-jit -o > test.lua`
